# 꿈땅새땅 청소년부 교적부 — 인수인계 문서

**이 문서를 읽는 분께.** 청소년부 교적부(주소록·셀편성·생일·교사연락처)를 웹사이트로 옮겨 둔 것입니다.
앞으로 이걸 맡으시게 되었다면, 이 문서 하나만 보고도 굴릴 수 있게 적었습니다.

| | |
|---|---|
| **사이트 주소** | <https://dreamland-newland.github.io/Our-Children/> |
| **화면(코드)이 사는 곳** | GitHub 저장소 — 무료 |
| **아이들 자료가 사는 곳** | Supabase — 무료 |
| **가입메일 알림 받는 사이트** | Brevo — 무료 |
| **매달 드는 돈** | 없습니다 |

## 0. 넘겨받으셨다면, 이 순서대로

**① 계정들을 넘겨받으세요 (제일 중요합니다)**

이 교적부는 **전임자의 개인 계정** 위에서 돌아갑니다. 이것만 놓치면 나중에 아무것도 못 고칩니다.

| 계정 | 무엇을 하는 곳 | 로그인 방법 |
|---|---|---|
| **GitHub** | 사이트 화면(코드)이 올라가 있는 곳 | Gmail 계정으로 로그인 |
| **Supabase** | 아이들 자료가 들어 있는 곳 | GitHub 계정으로 로그인 |
| **Brevo** | 가입 신청 메일 알림을 보내 주는 곳 — [4번](#가입-신청이-오면-메일로-알림-받기) 참고 | Gmail 계정으로 로그인 |

**세 곳 모두 전임자의 Gmail 계정 하나로 열립니다.** 그 계정만 넘겨받으면 셋 다 들어갈 수 있습니다.

> ### ⚠️ 비밀번호는 이 문서에 적지 마세요
> **이 저장소는 누구나 볼 수 있는 공개 저장소입니다.** (GitHub Pages 무료 플랜은 공개만 됩니다.)
> 여기에 적은 비밀번호는 전 세계에 공개되고, 지워도 **기록(커밋 히스토리)에는 남습니다.**
> 그 계정 하나가 GitHub·Supabase·Brevo 셋 다의 열쇠이고, 결국 **아이들 명단 전체**입니다.
>
> 계정과 비밀번호는 **문서 밖에서** 넘기세요 — 직접 만나서, 전화로, 종이 쪽지로.
> 받으신 뒤에는 **바로 비밀번호를 바꾸고 2단계 인증을 켜 주세요.**
> (혹시 실수로 올렸다면, 파일에서 지우는 것으로는 부족합니다. **비밀번호부터 바꾸세요.**)

**② 교적부 관리자 권한을 넘겨받으세요**

사이트에서 **회원가입 → 전임자가 승인 → 전임자가 «관리자로» 지정 → 전임자가 본인 관리자 내리기**
순서입니다. 자세한 건 [4. 관리자 일](#4-관리자-일--가입-승인과-권한-넘기기) 을 보세요.

**③ 백업을 한 번 받아 두세요**

개요 화면 → **📥 엑셀 받기 (교적부 전체)**. 5개 시트짜리 파일 하나가 받아집니다.
이 파일만 있으면 최악의 경우에도 명단은 복구됩니다.
**단, 아이들 실명·연락처가 들어 있으니 개인 컴퓨터나 교회 드라이브에만 두세요.**

**④ 한 바퀴 둘러보세요**

주소록 → 셀편성 → 생일 → 올해 중1 → 교사·간사 → 가져오기. 각 화면이 뭘 하는지는 [2번](#2-평소에-하는-일)에 있습니다.

## 1. 어떻게 굴러가나요 (딱 이만큼만 아시면 됩니다)

```
   선생님 휴대폰/PC
        │  주소를 열면
        ▼
   GitHub Pages ────────  화면(글씨·버튼·색). 여기엔 아이들 정보가 없습니다.
        │  자료를 달라고 물어보면
        ▼
   Supabase ────────────  아이들 명단·셀편성·사진이 진짜로 들어 있는 곳.
                          누가 무엇을 볼 수 있는지도 여기서 정합니다.
```

기억할 것은 두 가지입니다.

- **아이들 정보는 GitHub 에 없습니다.** 그래서 저장소가 공개여도 괜찮습니다.
- **누가 무엇을 볼 수 있는지는 Supabase 가 정합니다.** 화면에서 가리는 게 아니라
  서버가 아예 내주지 않습니다. 브라우저 개발자도구를 열어도 안 나옵니다.

### 누가 무엇을 볼 수 있나

| | 그냥 들어온 사람 | 로그인한 교사진 |
|---|---|---|
| 이름 · 성별 · 학년 · 학교 · 생년월일 · 셀 | 보임 | 보임 |
| 학생 휴대폰 · 집주소 | **안 보임** | 보임 |
| 어머니·아버지 성함/연락처 | **안 보임** | 보임 |
| 형제관계 · 특이사항(알레르기 등) | **안 보임** | 보임 |
| 프로필 사진 | **안 보임** | 보임 |
| 교사·간사 전화번호 | **안 보임** | 보임 |

**가입은 관리자 승인제**입니다. 아무나 신청할 수 있지만, 승인 전에는 로그인해도
그냥 들어온 사람과 똑같이만 보입니다.

## 2. 평소에 하는 일

| 화면 | 여기서 하는 일 |
|---|---|
| **개요** | 인원 한눈에 보기, **올해 중1 얼굴 익히기**(이름+사진), 이번 달 생일, 전체 백업 받기 |
| **주소록** | 아이 찾기·등록·수정, 프로필 사진 올리기, 장기결석·전출 표시 |
| **셀편성** | 셀 명단 보기, **모의편성**으로 새 편성 짜기, 지난 편성 열어보기 |
| **생일** | 월별 생일 명단. 자동으로 만들어집니다 (따로 관리하지 않습니다) |
| **올해 중1** | 새로 올라온 중1. 이것도 자동입니다 |
| **교사·간사** | 선생님 연락처. **관리자는 여기서 가입 승인**을 합니다 |
| **가져오기** | 엑셀로 한꺼번에 넣기 |

### 아이 한 명 고치기

주소록에서 이름을 누르면 신상이 열리고, **편집**을 누르면 고칠 수 있습니다.
파일로 올리는 것보다 이게 훨씬 빠릅니다.

- **학년 칸은 비워 두세요.** 생년월일만 있으면 저절로 계산되고 해마다 올라갑니다
- 생년월일을 모르면 **«태어난 해»** 칸에 `2013` 처럼 연도만 적어도 됩니다
- **하늘아이**(초등부에서 올라온 아이)는 체크만 해 두면 어디서나 배지로 보입니다
  («올해 중1» 화면 위의 **하늘아이 표시** 체크를 끄면 주소록·셀편성·개요까지 한꺼번에 배지가 사라집니다)
- 사진을 고르면 **자르는 창**이 뜹니다. 네모 안쪽을 끌어 위치를, 귀퉁이를 끌어 크기를 맞추세요

### 표에서 바로 거르기

주소록 표의 **칸 이름 옆 ▾** 를 누르면 그 칸으로 거를 수 있습니다
(이름·성별·학년·학교·생년월일·셀·전화번호·보호자·특이사항).

- 목록에는 **지금 조건에서 몇 명인지**가 같이 나옵니다
- 걸어 두면 칸 머리에 파란 칩이 붙고, 칩의 **✕** 로 그 필터만 뺄 수 있습니다
- **위쪽 드롭다운과 같이 움직입니다** — 어느 쪽에서 걸든 서로 반영됩니다
- 맨 왼쪽 **#** 은 걸러 놓은 목록의 **순번**입니다 (교적 번호가 아닙니다.
  교적 번호는 그 칸에 마우스를 올리면 나옵니다)
- 오른쪽 위 숫자는 **«걸러진 수 / 지금 우리 부서 전체»** 로 보여 줍니다

### «재적 / 장기결석 / 졸업 / 전출» 정리

| 주소록에서 고르면 | 보이는 아이 |
|---|---|
| **지금 우리 부서 아이들** (기본) | 잘 나오는 아이 + 오래 못 본 아이 |
| └ 잘 나오는 아이만 | «재적» |
| └ 오래 못 본 아이만 | «장기결석» |
| **졸업 — 청년부로 올라감** | 고3을 지나 자동으로 빠진 아이 |
| **전출 — 다른 교회로 옮김** | 직접 «전출» 로 바꾼 아이 |

**장기결석 아이도 셀편성에는 그대로 남습니다** — 담당 선생님이 계속 챙기셔야 하니까요.

### 셀편성 짜기

**셀편성 → ✏️ 편집 (모의편성)** 을 누르면 마음껏 만져도 되는 연습 상태가 됩니다.
**«저장하기»를 누르기 전까지는 아무에게도 보이지 않습니다.**

- 아이 줄을 **끌어서** 다른 셀 카드에 놓으면 옮겨집니다 (휴대폰에서는 줄 오른쪽 **⇄** 버튼)
- 이름 옆 잔글씨로 **성별 · 나이 · 학교 · 하늘아이 · 남매**가 보이고,
  마우스를 올리면 **형제자매(주황)와 같은 학교 친구(파랑)** 가 다른 셀에서도 함께 밝혀집니다
- 셀 카드 아래 **🙋 리더·헬퍼** 로 셀리더·셀헬퍼를 정합니다 (여러 명 가능, 없어도 됩니다)
- **↶ 되돌리기** 30단계 (`Ctrl+Z`)
- **💾 임시저장** 으로 여러 안을 만들어 두고 **📂 임시저장 목록** 에서 비교할 수 있습니다
  (임시저장은 **내 브라우저에만** 있습니다. 다른 선생님에게는 안 보입니다)
- **저장하기** 를 누르면 그때 «새 버전» 으로 기록됩니다. 지난 편성은 지워지지 않고
  위쪽 드롭다운에서 언제든 다시 볼 수 있습니다

고3이던 아이들은 «졸업(청년부)» 이 되어 목록에서 빠지고, 기록은 그대로 남습니다.

새로 올라온 중1만 등록해 주시면 됩니다 — 한 명씩은 주소록에서, 여러 명은 [엑셀로](#5-엑셀로-주고받기).

## 4. 관리자 일 — 가입 승인과 권한 넘기기

관리자는 **여러 명** 둘 수 있습니다. 아래 내용은 관리자에게만 보입니다.

### 가입 승인

신청이 들어오면 **교사·간사** 화면 위에 「승인 대기 N건」 배너가 뜹니다.
**교사·간사 → 👥 가입 승인 · 계정**

| 보이는 것 | 뜻 |
|---|---|
| 이름 · 아이디 · **휴대폰번호** · 신청일 | 아는 분이 맞는지 확인하는 데 씁니다 (번호는 관리자에게만 보입니다) |
| «나예요! ○○○» 배지 | 본인이 명부에서 고른 자리입니다 |
| 가운데 **드롭다운** | «이 사람은 명부의 누구»인지 관리자가 직접 고르거나 바꿉니다 |
| **승인** / **거절** | 승인해야 계정이 열립니다 |

- 명부에 **없는 분**도 «명부 연결 안 함» 으로 두고 승인하면 정상적으로 쓰실 수 있습니다
- 승인한 뒤에도 드롭다운으로 **연결을 언제든 바꾸거나 풀 수 있습니다**
- **거절**은 신청을 지웁니다. 같은 아이디로 다시 신청할 수 있습니다
- 신청 알림이 번거로우면 **🔐 가입 신청 설정 → «가입 신청 받기» 끄기**

### 관리자 넘기기 ★ 인수인계의 핵심

**이 순서를 꼭 지켜 주세요.**

1. 새 담당자가 **회원가입** 신청
2. 지금 관리자가 **승인**
3. 👥 가입 승인 · 계정에서 그분을 **«관리자로»** 지정
4. 그다음에 본인 **«관리자 내리기»** (또는 계정 해제)

**마지막 관리자는 내려올 수 없습니다.** 관리자가 한 명도 없어 교적부가 잠기는 일은
서버에서 막아 두었으니 걱정하지 않으셔도 됩니다.

**계정 해제하면** 그분의 로그인만 막히고 **교적 자료는 하나도 지워지지 않습니다.**
명부의 «가입» 표시가 풀려 후임자가 그 자리를 쓸 수 있고, 아이디도 다시 쓸 수 있습니다.

### 가입 신청이 오면 메일로 알림 받기

신청이 들어온 걸 모르고 지나치지 않도록, **관리자 메일로 바로 알림**을 보낼 수 있습니다.
받는 사람은 **교사·간사 → 🔔 알림 설정** 에서 언제든 바꿀 수 있습니다
(담당이 바뀌면 여기부터 새 담당자 주소로 고쳐 주세요).

**이미 설치되어 있습니다.** 새로 세울 일이 생기면 [부록 A-7](#a-7-가입-알림-메일-brevo--선택) 을 보세요.

> **Brevo 키는 90일 동안 한 번도 안 쓰면 자동으로 만료됩니다.** 그래서 관리자에게
> 두 달에 한 번 «알림이 살아 있습니다» 라는 점검 메일을 자동으로 보내 키를 계속 살려 둡니다.
> 이 점검 메일이 어느 순간 안 온다면, 알림 기능이 조용히 멈춘 것일 수 있으니 확인해 보세요.

### «문의는 이쪽으로»

가입 신청을 마친 분에게 **지금 관리자들의 이름·구분·휴대폰번호**가 보입니다.
승인을 기다리다 답답할 때 연락하시라는 뜻입니다.
이 번호는 **계정을 실제로 만든 사람에게만** 나갑니다 — 구경하는 방문자에게는 한 줄도 안 나갑니다.

## 6. 이럴 땐 이렇게

**사이트가 안 열려요 / 자료가 안 나와요**
Supabase 대시보드에 들어가 보세요. 무료 플랜은 아주 오랫동안 아무도 안 쓰면
프로젝트가 잠시 멈출 수 있는데, 대시보드에서 되살리기(Restore)를 누르면 돌아옵니다.

**바꿨는데 화면에 그대로예요**
브라우저가 예전 화면을 기억하고 있는 겁니다. 시크릿 모드에서 조회해 보거나,
휴대폰이면 앱을 완전히 닫았다 여세요.

**가입이 "Email address is invalid" 로 실패해요**
Supabase → **Authentication → Sign In / Providers → Email** 에서
**Confirm email** 을 **꺼** 주세요. 우리는 이메일이 아니라 아이디로 로그인하는데,
앱이 내부적으로 `아이디@kkumttang.local` 이라는 가짜 이메일을 쓰기 때문입니다.

**비밀번호를 잊었어요**
Supabase → **Authentication → Users** 에서 관리자가 새 비밀번호로 바꿔 줄 수 있습니다.
(가짜 이메일이라 «비밀번호 찾기» 메일은 못 보냅니다.)

**엑셀을 올렸는데 0건이래요**
화면이 **앱이 파일에서 읽은 앞부분을 표로** 보여 줍니다. 엑셀 칸 주소(A·B·C)와 줄 번호가
그대로 나오니, 이름이 어느 칸에 있는지 맞춰 보세요. 대개 머리글 위의 메모가 원인입니다.

**데모 화면(노란 배너)이 떠요**
`assets/js/config.js` 에 Supabase 주소·키가 안 들어간 상태입니다. [부록 A](#부록-a--처음부터-다시-세우기) 참고.

## 부록 A — 처음부터 다시 세우기

계정을 잃어버렸거나, 다른 부서에서 똑같이 만들고 싶을 때 보시면 됩니다.
평소에는 볼 일이 없습니다.

### A-1. Supabase 만들기

1. <https://supabase.com> 가입 → **New project** (무료 플랜으로 충분합니다)
2. Region 은 **Northeast Asia (Seoul)**
3. Database Password 는 적어 두세요

### A-2. 표 만들고 자료 넣기

좌측 **SQL Editor → New query** 에 아래 파일 내용을 붙여넣고 **Run**.

| 순서 | 파일 | 하는 일 |
|---|---|---|
| 1 | `supabase/01_schema.sql` | 표·권한·가입 승인 로직 만들기 |
| 2 | `supabase/05_cell_seat.sql` | 셀리더·셀헬퍼 칸 추가 |
| 2-1 | `supabase/06_notify_email.sql` | *(선택)* 가입 신청 메일 알림 |
| 3 | 백업 엑셀 또는 `02_seed.REAL.sql` | 실제 자료 넣기 |
| 4 | `supabase/04_photos.sql` | *(선택)* 사진을 쓰려면 |
| 5 | `supabase/03_public_all.sql` | *(선택·비권장)* 연락처까지 전부 공개로 |

연습만 해보려면 `supabase/02_seed.sample.sql`(가명)을 쓰세요.

### A-3. 이메일 확인 끄기 ★

**Authentication → Sign In / Providers → Email**

- **Confirm email** → **끄기**
- Enable Email provider → 켜둔 채로

이걸 안 끄면 가입이 안 됩니다. 아이디로 로그인하는 구조라 그렇습니다.

### A-4. 키 넣기

**Settings → API / API Keys** 의 두 값을 `assets/js/config.js` 에 넣습니다.

```js
export const SUPABASE_URL      = "https://xxxxxxxx.supabase.co";
export const SUPABASE_ANON_KEY = "sb_publishable_xxxxxxxxxxxx";
```

두 번째는 **Publishable key**(`sb_publishable_…`)입니다. 안 보이면 **Legacy API Keys** 의
`anon` 키를 쓰세요 — 둘 다 «비로그인 권한» 이라 동작은 같습니다.

> 이 키는 공개용이라 GitHub 에 올려도 됩니다. 실제 권한은 서버가 정합니다.
> **`service_role` / `sb_secret_…` 키는 절대 넣지 마세요.**

### A-5. GitHub Pages 로 올리기

저장소에 파일을 올리고 **Settings → Pages → Source** 를 **GitHub Actions** 로 두면
`.github/workflows/pages.yml` 이 알아서 배포합니다.
(**Deploy from a branch → main / (root)** 로 두어도 됩니다.)

주소는 `https://<계정>.github.io/<저장소>/` 입니다.

- 무료 플랜에서는 **공개 저장소만** Pages 를 쓸 수 있습니다
- 저장소를 비공개로 해도 **배포된 사이트는 공개**입니다 (비공개는 소스코드만 가립니다)
- 올리기 전에 실명 파일이 섞이지 않았는지 꼭 확인하세요

### A-6. 첫 관리자 만들기

배포된 주소에서 **회원가입** 하세요.
**가장 먼저 가입한 한 사람만 승인 없이 바로 열리고, 자동으로 관리자가 됩니다**
(승인해 줄 사람이 아직 없으니까요). 그러니 담당자가 제일 먼저 가입하세요.

### A-7. 가입 알림 메일 (Brevo) — 선택

`supabase/06_notify_email.sql` 파일 맨 위에 같은 안내가 더 자세히 적혀 있습니다.

1. <https://www.brevo.com> 무료 가입 — **도메인 없이 메일 주소 하나만 인증하면 하루 300통 무료**
2. **Senders, Domains & Dedicated IPs → Senders → Add a sender** 로 내 메일 주소를 등록하고,
   받은 확인 메일의 링크를 클릭 (초록 체크가 떠야 합니다)
3. **SMTP & API → «API keys & MCP»** 탭에서 키를 만들어 복사
   - ★ 같은 화면의 **«SMTP» 탭이 아닙니다.** 거기서 만든 키(`xsmtpsib-`)는 작동하지 않습니다
   - 우리가 쓸 키는 **`xkeysib-`** 로 시작합니다. 한 번만 보여 주니 그때 복사하세요
   - 만료는 **«No expiration»**
4. `06_notify_email.sql` 전체를 Supabase **SQL Editor** 에 붙여넣고 Run
5. 맨 아래 «설정 넣기» 의 `--` 를 지우고 본인 것으로 채워 **한 번 더 Run**
   - ★ **사이트 주소는 저장소 이름까지 넣으세요.** `https://내계정.github.io` 까지만 넣으면
     메일 속 «교적부에서 확인하기» 버튼이 엉뚱한 곳으로 갑니다
6. 교적부 → 교사·간사 → **🔔 알림 설정 → 시험 메일 보내기** 로 확인

실제 가입 신청 메일이 어떻게 생겼는지 미리 보려면, SQL Editor 에서
`select public.notify_preview();` — 교적부에는 아무 흔적도 남지 않습니다.

**안 오면** `supabase/07_notify_check.sql` 을 Run 해 보세요. 아무것도 바꾸지 않고
어디서 막혔는지만 알려 줍니다 (브레보 응답이 `401` 이면 키가 틀린 것, `400` 이면 보내는 주소 인증이 덜 된 것).

> **API 키는 브라우저로 절대 나가지 않습니다.** Supabase 안에만 있고, 교적부 화면에서는

## 부록 B — 무엇을 어떻게 막고 있나

궁금하시거나, 나중에 «이거 안전한가요?» 라는 질문을 받으실 때 보여 주시면 됩니다.

| | 비로그인 | 승인 전 계정 | 승인된 교사진 | 관리자 |
|---|---|---|---|---|
| 이름·학년·학교·셀 보기 | O | **X** | O | O |
| 연락처·주소·보호자·특이사항 | **X** | **X** | O | O |
| 등록·수정·삭제 | **X** | **X** | O | O |
| 가입 승인 · 관리자 지정 | **X** | **X** | **X** | O |
| 셀편성 버전 삭제 | **X** | **X** | **X** | O |

«승인 전 계정» 이 비로그인보다 더 막혀 있는 것은 실수가 아닙니다.
승인 전에는 서버가 **한 줄도** 내주지 않습니다.

실제 Postgres 에 스키마를 올려 다음을 확인했습니다.

- 비로그인으로 학생·교사·셀 표에 **INSERT / UPDATE / DELETE 전부 거부**
- 비로그인으로 `profiles`, `app_settings` 읽기 거부
- 비로그인·계정 없는 토큰으로 관리자 연락처 호출 → 0줄
- **승인 전 계정**으로 학생·교사·셀편성 조회 → 0줄, 등록·수정·삭제 전부 거부
- 숨긴 칸을 `WHERE` · `ORDER BY` · `select *` 에 끼워 넣어 우회 시도 → 전부 거부
- 교사 전화번호를 알아내 «나예요!» 를 통과하는 사칭 시나리오 → 번호 비공개 + 관리자 승인으로 차단
- 비관리자가 버전 삭제 / 가입 설정 변경 / 관리자 권한 부여 시도 → 전부 거부
- 브라우저 콘솔에서 자료 함수를 직접 호출 → 전부 거부

정말 전부 공개해야 한다면 `supabase/03_public_all.sql` 실행 + `config.js` 의
`PUBLIC_SCOPE` 를 `"all"` 로 바꾸면 됩니다.
(교사 전화번호는 사칭 방지를 위해 이때도 공개되지 않습니다.)
