# 꿈땅새땅 청소년부 교적부

교회 청소년부 교적부를 GitHub Pages 로 운영하는 웹앱입니다.
지금 쓰시는 구글시트를 대체하려는 것이 아니라, 엑셀로 서로 주고받으며 함께 쓸 수 있습니다.

- **조회는 누구나** — 로그인 없이 주소록·셀편성·생일·올해 중1·교사연락처를 볼 수 있습니다.
  단, 휴대폰·집주소·보호자 연락처·특이사항은 **로그인한 교사진에게만** 보입니다.
- **등록·수정은 교사진만** — 아이디/비밀번호로 로그인해야 합니다.
- **가입은 관리자 승인제** — 누구나 신청할 수 있지만, 관리자가 승인해야 열립니다. 승인 전에는 로그인해도 서버가 한 줄도 내주지 않습니다.
- **«나예요!» 는 선택** — 교사·간사 명부에 있으면 본인 자리를 골라 연결할 수 있고, 명부에 없어도 신청할 수 있습니다. 연결은 관리자가 승인하면서 정합니다.
- **셀편성은 버전 관리** — 편집을 마치고 저장하는 시점에 등록일·등록자와 함께 버전으로 기록됩니다. 편집 중에는 30단계 되돌리기가 되고, 버전 삭제는 관리자만.
- **관리자는 넘길 수 있습니다** — 담당이 바뀌어도 화면에서 새 담당자에게 관리자를 넘기면 됩니다. 마지막 관리자는 내려올 수 없어 교적부가 잠기지 않습니다.
- **휴대폰 홈 화면에 앱처럼** — 접속하면 «홈 화면에 추가» 를 기기에 맞춰 안내합니다 (안드로이드는 설치 버튼, 아이폰은 공유→추가 방법). 한 번 닫으면 다시 뜨지 않습니다.
- **엑셀 통째로 주고받기** — 5개 시트짜리 교적부를 한 파일로 내려받고, 엑셀/CSV를 올리면 알아서 인식해 반영합니다.
- **학년은 저절로 올라갑니다** — 생년월일과 «올해가 몇 학년도인지» 로 계산합니다. 3월 1일이 지나면 모두 한 학년씩 올라가고, 고3이던 아이들은 졸업(청년부)으로 넘어가 교적·셀편성에서 빠집니다.

이 저장소를 GitHub Pages 로 올리기만 하면 **데모 모드**로 바로 동작합니다.
화면 구성과 인원 수는 실제와 같지만 **이름·연락처·주소는 전부 가명**입니다

변경사항은 그 브라우저에만 저장되므로, 교사진이 함께 쓰려면 아래 2단계가 필요합니다.

> 실제 아이들 정보는 저장소에 들어 있지 않습니다.

로컬에서 확인하려면 — 파일을 더블클릭하지 말고 간단한 서버로 여세요.

```bash
python3 -m http.server 8000
# → http://localhost:8000
```

## 2. Supabase 연결 (진짜로 함께 쓰기)

### 2-1. 프로젝트 만들기

1. <https://supabase.com> 가입 후 **New project** (무료 플랜으로 충분합니다).
2. Region 은 **Northeast Asia (Seoul)** 를 고르면 빠릅니다.
3. Database Password 는 따로 적어두세요.

### 2-2. 표(테이블) 만들고 데이터 넣기

좌측 메뉴 **SQL Editor** 에서 아래 순서대로 파일 내용을 붙여넣고 **Run** 합니다.

| 순서 | 파일 | 하는 일 |
|---|---|---|
| 1 | `supabase/01_schema.sql` | 표·권한(RLS)·가입 승인 로직 생성 |
| 2 | **`02_seed.REAL.sql`** | 실제 데이터 넣기 (학생 73 · 교사진 18 · 셀 13) |
| 3 | `supabase/04_photos.sql` | *(선택)* 학생 프로필 사진 쓰려면 실행 |
| 4 | `supabase/03_public_all.sql` | *(선택·비권장)* 연락처·주소까지 전부 공개로 바꾸기 |

**`02_seed.REAL.sql` 은 저장소에 없습니다.** 따로 받은 파일을 SQL Editor 에 붙여넣어
실행만 하세요. 실행하고 나면 실제 데이터는 Supabase 안에만 있고 깃허브에는 남지 않습니다.
(`.gitignore` 에 이미 등록해 두었으니 실수로 커밋될 일은 없습니다.)
연습만 해보고 싶다면 저장소에 있는 `supabase/02_seed.sample.sql`(가명)을 쓰세요.

시드 파일은 여러 번 실행해도 안전합니다 (이미 가입한 계정은 건드리지 않습니다).

### 2-3. 이메일 확인 끄기 ★ 중요

교사진은 이메일이 아니라 **아이디**로 로그인합니다.
앱이 내부적으로 `아이디@kkumttang.local` 형태의 가짜 이메일을 쓰기 때문에,
확인 메일 발송을 꺼야 가입이 됩니다.

**Authentication → Sign In / Providers → Email** 에서

- **Confirm email** → **끄기(off)**
- Enable Email provider → 켜둔 채로

### 2-4. 키 넣기

**Settings → API / API Keys** 에서 두 값을 복사해 `assets/js/config.js` 에 넣습니다.

```js
export const SUPABASE_URL      = "https://xxxxxxxx.supabase.co";
export const SUPABASE_ANON_KEY = "sb_publishable_xxxxxxxxxxxx";
```

두 번째 값은 **Publishable key**(`sb_publishable_…`)입니다.
예전에 만든 프로젝트라 그 항목이 안 보이면 **Legacy API Keys** 탭의 `anon` 키
(`eyJhbGciOi…`)를 쓰세요 — 둘 다 «비로그인 권한»이라 동작은 똑같습니다.
(Supabase 는 legacy `anon`·`service_role` 키를 2026년 말에 없앨 예정이라고 안내하고 있습니다.)

> 이 키는 공개용이라 깃허브에 올려도 됩니다. 실제 권한은 서버의 RLS 정책이 결정합니다.
> **`service_role` / `sb_secret_…` 키는 절대 넣지 마세요.**

## 3. GitHub Pages 로 올리기

```bash
git init
git add .
git commit -m "꿈땅새땅 교적부"
git branch -M main
git remote add origin https://github.com/<계정>/<저장소>.git
git push -u origin main
```

저장소 **Settings → Pages → Source** 를 **GitHub Actions** 로 두면
`.github/workflows/pages.yml` 이 알아서 배포합니다.
(또는 Source 를 **Deploy from a branch → main / (root)** 로 두어도 됩니다.)

주소는 `https://<계정>.github.io/<저장소>/` 입니다.

### 저장소는 공개해도 되나요?

**됩니다.** 실제 아이들 정보는 저장소가 아니라 Supabase 에만 있기 때문입니다.
저장소에 올라가는 것은 코드와 가명 예시 데이터뿐입니다.

- 무료 플랜에서는 **공개 저장소만** GitHub Pages 를 쓸 수 있습니다
  (비공개 저장소로 Pages 를 쓰려면 GitHub Pro 이상이 필요합니다).
- 저장소를 비공개로 해도 **배포된 사이트 자체는 공개**입니다. 비공개는 소스코드만 가립니다.
- 커밋 전에 `git status` 로 `02_seed.REAL.sql` 이나 실제 엑셀이 섞이지 않았는지 한 번 확인하세요.
  한번 커밋되면 나중에 지워도 커밋 기록에 남습니다.

## 4. 첫 로그인과 가입 승인

### 맨 처음 한 번 — 관리자 만들기

1. 배포된 주소에서 **회원가입**
2. 이름과 휴대폰번호 입력 → 명단에서 본인 카드가 뜨면 **나예요!**
3. 아이디(영문 소문자·숫자 4~20자)와 비밀번호(6자 이상) 설정

**가장 먼저 가입한 한 사람만 승인 없이 바로 열리고, 자동으로 관리자**가 됩니다
(승인해 줄 사람이 아직 없으니까요).
그러니 배포하자마자 **솔님이 제일 먼저 가입**해 주세요.

### 그다음부터 — 신청하고, 관리자가 승인

선생님이 하는 일은 똑같습니다. 이름·휴대폰번호를 적고, 명부에서 본인이 보이면 «나예요!»를
누르고(**안 보여도 «건너뛰기»로 계속 진행**), 아이디와 비밀번호를 정하면 끝입니다.
그러면 «신청이 접수되었습니다» 화면이 뜨고 **로그인은 아직 되지 않습니다.**

관리자에게는 **교사·간사** 화면 위에 「**승인 대기 N건**」 배너가 뜹니다.

**교사·간사 화면 → 👥 가입 승인 · 계정**

| 보이는 것 | 뜻 |
|---|---|
| 이름 · 아이디 · **휴대폰번호** · 신청일 | 아는 분이 맞는지 확인하는 데 씁니다 (번호는 관리자에게만 보입니다) |
| «나예요! ○○○» 배지 | 본인이 명부에서 고른 자리입니다 |
| 가운데 **드롭다운** | 관리자가 «이 사람은 명부의 누구»인지 직접 고르거나 바꿉니다 |
| **승인** / **거절** | 승인하면 그때 계정이 열리고 명부에 «가입» 표시가 붙습니다 |

- 교사·간사 명부에 **없는 분**은 «명부 연결 안 함»으로 두고 승인하면 됩니다.
  계정은 정상적으로 열리고, 교사·간사 명단과 생일명단에는 나오지 않습니다 (배지로 «명부 밖» 표시).
- 승인한 뒤에도 같은 드롭다운으로 **명부 연결을 언제든 바꾸거나 풀 수 있습니다.**
- **거절**은 신청을 지웁니다. 같은 아이디로 다시 신청할 수 있습니다.

### «문의는 이쪽으로» — 관리자 연락처

신청을 마치면 **«신청이 접수되었습니다»** 화면 아래에 지금 관리자인 분들의
**이름 · 구분 · 휴대폰번호**가 뜹니다. 승인 대기 중에 로그인을 시도했을 때도 같이 나옵니다.
번호를 누르면 전화가 걸리고(PC에서는 복사됩니다).

- 명부에 연결된 관리자는 **교사 명부의 번호**, 명부 밖 관리자는 **신청할 때 적은 번호**를 씁니다
- 관리자를 여러 명 두면 **여러 명이 다 표시**됩니다

> **이 번호가 인터넷에 공개되나요?** 아닙니다. 이 목록은 **실제로 계정을 만든 사람에게만**
> 내려갑니다. 그냥 가입 화면을 구경하는 방문자에게는 한 줄도 나가지 않습니다.
> (`admin_contacts()` 는 로그인 세션이 있고 `profiles` 에 행이 있는 사람만 부를 수 있습니다.
> 비로그인 조회 → 0줄, 계정 없는 토큰 → 0줄로 확인했습니다.)
> 마음에 걸리시면 관리자의 교사 명부 번호를 대표번호로 바꿔 두셔도 됩니다.

> **승인 전에는 정말 아무것도 못 보나요?** 네. 로그인하지 않은 방문자와 똑같이
> 이름·학년·학교·셀까지만 보입니다. 휴대폰·집주소·보호자 연락처·사진은 안 보입니다.
> 화면에서 가리는 게 아니라 **서버(RLS)가 한 줄도 내보내지 않습니다** — 승인 전 계정으로
> 학생·교사·셀편성을 조회하면 결과가 0줄입니다.

### 관리자 넘기기 · 늘리기 ★

담당이 바뀌어도 교적부가 잠기지 않도록, 관리자는 화면에서 직접 넘길 수 있습니다.

**교사·간사 화면 → 👥 가입 승인 · 계정** (관리자에게만 보입니다)

| 버튼 | 하는 일 |
|---|---|
| **관리자로** | 그 교사진을 관리자로 지정합니다. 관리자는 **여러 명** 둘 수 있습니다. |
| **관리자 내리기** | 관리자 권한만 거둡니다. 로그인·수정 권한은 그대로입니다. |
| **계정 해제** | 그만두신 분의 로그인 권한을 거둡니다. |

**담당을 넘길 때는 이 순서로 하세요.**

1. 새 담당자가 가입을 신청하고, 관리자가 **승인**합니다
2. 👥 가입 승인 · 계정에서 그분을 **관리자로** 지정합니다
3. 그다음 본인의 **관리자 내리기** 를 누릅니다 (또는 계정 해제)

**마지막 관리자는 내려올 수 없습니다.** 실수로 관리자가 한 명도 없는 상태가 되는 것을
서버에서 막아두었으니, 교적부가 잠길 걱정은 하지 않으셔도 됩니다.
(관리자가 한 명뿐이면 «관리자 내리기» 버튼이 아예 눌리지 않습니다.)

**계정 해제 후에는 어떻게 되나요?** 교적 자료는 하나도 지워지지 않습니다.
그분의 로그인만 막히고, 교사 명부의 «가입» 표시가 풀려 나중에 다시 가입하거나
후임자가 그 자리를 쓸 수 있습니다. 아이디도 함께 비워지므로 같은 아이디를 다시 쓸 수 있습니다.

> 급하게 손봐야 할 때는 Supabase **Table Editor → profiles** 에서
> `approved` · `is_admin` 을 직접 `true` 로 바꾸는 방법도 있습니다.

### 신청 자체를 잠그고 싶을 때

승인제라 모르는 사람이 신청해도 아무것도 볼 수 없지만, 신청 알림이 자꾸 오면 번거로우실 수 있습니다.

**교사·간사 화면 → 🔐 가입 신청 설정 → «가입 신청 받기» 끄기**

끄면 아무도 새로 신청할 수 없습니다. 기존 계정은 그대로 쓰입니다.
새 선생님이 오시면 잠깐 켰다가 다시 끄시면 됩니다.

| **가져오기** | 엑셀/CSV 업로드 → 자동 인식 → 미리보기 → 반영 *(로그인 필요)* |

### 모의편성 · 임시저장

**셀편성 → ✏️ 편집 (모의편성)** 을 누르면 모의편성 모드입니다.
저장을 누르기 전까지는 **아무에게도 보이지 않습니다.**

| 버튼 | 하는 일 |
|---|---|
| **💾 임시저장** | 지금 짜던 안을 **내 브라우저에만** 이름 붙여 보관합니다. 「모의 1차 (8/18)」처럼 자동으로 이름이 붙고, 목록에서 **이름 바꾸기**로 고칠 수 있습니다. 여러 안을 만들어 두고 **불러오기**로 비교하세요 |
| **저장하기** | 모두가 보는 **버전으로 확정**합니다 |
| **취소** | 짜던 것을 버리고 나갑니다 |

임시저장은 최대 20개까지 쌓아둘 수 있고, 확정 저장을 해도 지워지지 않습니다.
필요 없어지면 목록에서 **삭제**하세요.

### 편성 이름 바꾸기 · 지난 편성으로 되돌리기

- **✏️ 이름 바꾸기** — 이미 저장된 편성의 이름과 메모를 고칩니다. 편성 내용은 그대로입니다
- **↩ 이 편성으로 되돌리기** — 지난 버전을 골랐을 때 나옵니다. 그 편성을 **그대로 복사해 새 최신 편성**을 만듭니다.
  지우는 게 아니라 새로 만드는 것이라, 되돌린 뒤에도 그 사이 편성들이 기록으로 남습니다

### 마우스로 끌어 옮기기

**셀편성 → ✏️ 편집** 을 누르면 모의편성 모드입니다. 저장을 누르기 전까지는 **아무에게도 보이지 않습니다.**

- 학생 줄을 **잡아서 다른 셀 카드 위에 놓으면** 배정이 바뀝니다
- 셀 카드 아래 **🙋 리더·헬퍼** 버튼을 누르면 **그 셀 아이들만** 뜹니다.
  이름 오른쪽 «리더»·«헬퍼» 를 눌러 정하고, 한 번 더 누르면 풀립니다.
  **리더도 헬퍼도 여러 명이어도 되고, 아무도 없는 셀은 그냥 비워 두면 됩니다.**
  정하고 나면 이름 옆에 배지가 붙고, 셀 이름 아래에 «리더 ○○○ · 헬퍼 ○○○» 로 요약됩니다
- 위쪽에 붙어 있는 **미배정 칸**은 늘 보입니다. 여기로 끌면 셀에서 빠지고, 여기서 끌어 셀에 넣습니다
- 이름 옆 잔글씨로 **성별 · 나이 · 학교 · 하늘아이 · 남매**가 보이고,
  마우스를 올리면 **형제자매(주황)와 같은 학교 친구(파랑)** 가 다른 셀에서도 함께 밝혀집니다
- 셀 이름 아래에 **남녀 수와 학년 분포** 요약이 붙습니다
- 지난 편성에서 자리가 바뀐 아이에게는 **«이동»** 표시가 붙습니다
- **되돌리기 30단계** (Ctrl/⌘+Z) 가 드래그에도 그대로 적용됩니다
- 맨 아래 **＋ 셀 추가** 타일로 새 셀을 만들 수 있습니다
- **장기결석자·기타 칸은 셀을 몇 개 만들든 늘 맨 뒤**에 옵니다
- 내가 담당하는 셀은 **맨 앞**에 초록 테두리로 표시됩니다
- 휴대폰처럼 끌기가 어려운 곳에서는 각 줄의 **⇄** 버튼을 쓰세요

**짜다 만 편성은 이 브라우저에 자동으로 보관됩니다.** 다른 화면에 갔다 와도 그대로 있고,
창을 닫았다 열면 «짜던 편성이 있습니다 → 이어서 하기» 안내가 뜹니다.
저장하거나 «버리기» 를 누르면 정리됩니다. (되돌리기 기록은 창을 닫으면 초기화됩니다.)

### 셀편성 버전이 만들어지는 방식

1. **편집** 버튼 → 편집 모드 진입 (셀 추가/삭제, 학생 배정·이동)
2. 고치는 동안에는 화면에만 남아 있습니다 (아직 저장 안 됨)
3. **저장하기** → 버전 이름을 정하고
   - *새 버전으로 저장* — 오늘 날짜·저장한 교사 이름으로 새 버전 기록, 기존 버전은 그대로 보존
   - *현재 버전에 덮어쓰기* — 등록일은 유지, 최종 저장 시각만 갱신

지난 버전은 상단 드롭다운에서 언제든 그대로 열람할 수 있습니다.

### 프로필 사진

사진을 고르면 **자르는 창**이 열립니다. 사진 위의 네모를 **안쪽을 끌어 위치**를,
**귀퉁이를 끌어 크기**를 맞추면 그 부분만 프로필 사진이 됩니다 (정사각형 유지).
휴대폰 사진의 회전도 알아서 바로잡습니다.

### 프로필 사진 (저장 방식)

주소록에서 학생을 **편집**하면 왼쪽 위 동그라미를 눌러 사진을 올릴 수 있습니다.

- 정사각형으로 잘라 **400px 로 줄여서** 올리므로 원본이 커도 괜찮습니다
- **저장을 눌러야** 실제로 올라갑니다 (미리보기 먼저 보여드립니다)
- 사진이 없으면 이름 끝 두 글자 동그라미가 대신 보입니다
- 주소록·상세·셀편성 카드에 함께 나타납니다

사진은 **비공개 저장소**에 들어가고, 로그인한 교사진에게만 1시간짜리 임시 링크가 발급됩니다.
주소를 복사해 다른 사람에게 보내도 열리지 않고, 로그아웃하면 바로 이니셜로 돌아갑니다.
아이들 얼굴이라 «전부 공개» 설정에서도 **항상 로그인해야** 보입니다.

> 사진을 쓰려면 `supabase/04_photos.sql` 을 한 번 실행해야 합니다.
> 실행하지 않으면 나머지 기능은 그대로 동작하고 사진 올리기만 안 됩니다.

### 올릴 수 있는 파일은 세 가지입니다

**가져오기 → 📥 양식 파일 받기** 로 받는 파일 한 개에 세 시트가 들어 있습니다.

| 시트 이름 | 무엇을 적나요 | 어디로 들어가나요 |
|---|---|---|
| **학생명단** | 아이들 인적사항 | 주소록. 있는 아이는 정보만 고쳐지고, 없던 아이는 새로 등록 |
| **셀편성** | 담당 선생님 아래로 `이름 · 역할` | 셀편성 화면에 **새 편성 버전**으로 (셀리더·셀헬퍼 포함) |
| **교사간사연락처** | 선생님·간사님 명부 | 교사·간사 화면 |

- **생일 명단과 «올해 중1» 화면은 따로 올리지 않습니다** — 생년월일만 있으면 저절로 만들어집니다.
- 새로 올라온 아이들만 올릴 때는 **시트 이름을 «올해중1»** 로 두면, 그때 **새로 등록되는 아이에게만**
  «하늘아이» 표시가 붙습니다. 이미 있는 아이는 정보만 고쳐집니다.
- 아이 한 명 고치기·셀 하나 옮기기는 파일보다 **앱에서** 하시는 편이 빠릅니다.

> **양식을 바꾸지 마세요 — 세 가지만 지키면 됩니다**
> 1. **머리글 줄의 칸 이름을 바꾸거나 지우지 마세요.** 순서를 옮기거나 안 쓰는 칸을 빼는 건 괜찮습니다.
> 2. **머리글 줄 위에 메모를 넣지 마세요.** 굳이 넣으신다면 «이름» «학년» «생일» 같은 낱말은 피해 주세요.
> 3. **시트 이름**은 양식에 있는 그대로 두세요.
>
> 올리시면 앱이 **«이 시트를 ○○로 봤습니다»** 와 **못 알아본 칸**을 먼저 보여 줍니다.

**«예시)» 줄은 올라가지 않습니다.** 양식 맨 왼쪽 칸에 `예시)` 라고 적힌 줄은 건너뛰니
지우지 않고 그대로 두고 그 아래에 이어서 적으셔도 됩니다. 아무것도 안 적고 양식을 그대로 올리면
«아직 안 적음» 이라고만 알려 주고 아무 일도 하지 않습니다.

**양식 파일 자체를 고치고 싶으면** 저장소의 `assets/templates/import-template.xlsx` 를
엑셀에서 고쳐 그대로 덮어쓰면 됩니다. 앱은 이 파일을 그대로 내려 줄 뿐이라 코드는 건드릴 필요가 없습니다.

### 내려받기 버튼은 어디서나 같은 모양입니다

모든 화면의 **📥 엑셀 받기** 버튼은 같은 자리·같은 이름이고, 파일 이름도 한 가지 모양입니다.

| 화면 | 받는 파일 |
|---|---|
| 개요 | `꿈땅새땅_교적부전체_20260818.xlsx` (5개 시트 한꺼번에) |
| 주소록 | `꿈땅새땅_주소록_20260818.xlsx` (지금 걸러 놓은 목록 그대로) |
| 셀편성 | `꿈땅새땅_셀편성_2026-2학기_20260818.xlsx` (지금 보고 있는 버전) |
| 생일 | `꿈땅새땅_생일명단_20260818.xlsx` |
| 올해 중1 | `꿈땅새땅_올해중1_20260818.xlsx` |
| 교사·간사 | `꿈땅새땅_교사간사_20260818.xlsx` |

### 파일 가져오기는 이렇게 됩니다

1. **올리기** — 엑셀/CSV를 올리면 열 이름을 보고 알아서 읽습니다. **이 단계에서는 교적부가 전혀 바뀌지 않습니다.**
2. **확인하기** — 파일에서 읽은 내용을 **표로 그대로** 보여 주고, 지금 교적부와 견줘
   **새로 등록 / 고칠 내용 / 그대로** 로 나눠 줍니다. 무엇이 어떻게 바뀌는지 한 줄씩 나옵니다.
3. **반영하기** — 맨 아래 **«반영하기»** 를 눌러야 저장됩니다.
   파일에 **없는 칸**과 **없는 아이**는 건드리지 않습니다.

> 셀편성을 **«현재 버전 받기»** 로 내려받으면 줄마다 «셀 · 담당 · 이름 · 자리 …» 가 채워져 있습니다.
> 엑셀에서 **«셀» 칸을 고쳐 다시 올리면 그 아이가 그 셀로 옮겨지고**, **«자리» 칸**으로 셀리더·셀헬퍼도 바꿀 수 있습니다.
> 옮김·자리 변경도 반영 전에 «변경» 목록에 그대로 표시됩니다.

### 파일 가져오기가 알아보는 것

- **한글 열 이름 자동 인식** — 이름 · 성별 · 학년 · 학교 · 생년월일 · 전화번호(연락처·휴대폰) ·
  어머니성함/연락처 · 아버지성함/연락처 · 형제관계 · 집주소 · 비고(특이사항) · 셀 · 구분 · 자리.
  띄어쓰기나 순서가 달라도 되고, **파일에 없는 열은 기존 값을 그대로 둡니다.**
- **생년월일 칸에 `2013` 처럼 연도만 적혀 있어도** 알아듣고 «태어난 해» 로 저장합니다.
  (내보내기도 같은 방식이라 구글시트와 그대로 왕복합니다.)
- **셀편성 표 두 가지를 모두 인식합니다.** 반영하면 **새 편성 버전**이 만들어집니다.
  - *세로형* — `교사/간사 · 이름 · 자리 · 학년 · 생년월일 · 전화번호` 를 위에서 아래로.
    **교사/간사 칸은 셀의 첫 줄에만 적어도** 됩니다(아래 빈 칸은 같은 셀로 봅니다).
    담당이 두 분이면 `김○○, 이○○` 처럼 쉼표로.
  - *가로 블록형* — 담당자 이름 아래 `이름 / 자리 / 학년 …` 블록이 옆으로 반복되는 형태
    (원본 출석부 형식). `장기결석자` 블록도 포함.
- **머리글 줄은 «가장 머리글다운 줄»로 고릅니다.** 맨 위에 «* 파란색 이름 = …» 같은 **메모가 있어도**
  그 줄을 머리글로 착각하지 않습니다.
- **셀리더 · 셀헬퍼** — 셀편성 표의 **«자리»** 칸에 `셀리더` · `셀헬퍼`(`리더` · `헬퍼` 도 됩니다)
  라고 적거나, 이름 칸에 `홍길동(리더)` · `★홍길동` 처럼 적어도 읽어옵니다.
  비워 두어도 되고, 나중에 셀편성 화면에서 체크로 정해도 됩니다.
  **아이들 중에서 세우는 자리**라 편성 버전마다 따로 기록되고, 새로 편성하면 새로 정합니다.
- **반영 전 미리보기** — 신규 / 변경 / 동일 을 항목별로 보여주고, 확인을 눌러야 저장됩니다.
- 같은 이름이 여러 명이면 생년월일이나 전화번호로 구분하고,
  그래도 애매하면 **확인필요**로 표시하고 건너뜁니다.

**가져오기 → 양식 파일 받기** 로 표준 양식을 내려받을 수 있습니다.

> **구글시트와 함께 쓰기** — 시트에서 «파일 → 다운로드 → Microsoft Excel(.xlsx)» 로 받은 파일을
> 그대로 올리면 됩니다. 반대로 «엑셀 전체 내려받기» 로 받은 파일은 구글 드라이브에 올려
> 시트로 열 수 있습니다. 시트를 계속 쓰시면서 교적부와 왔다갔다 할 수 있습니다.

## 5-1. 휴대폰에 앱처럼 설치하기 (PWA)

주소를 매번 찾지 않도록, 접속하면 화면 아래에 **홈 화면에 추가** 안내가 뜹니다.

| 기기 | 어떻게 보이나 |
|---|---|
| **안드로이드 · 크롬** | 「설치하기」 버튼 → 누르면 바로 설치됩니다 |
| **아이폰 · 아이패드 (사파리)** | 사파리는 자동 설치가 안 돼서 방법만 안내합니다 — 아래 **공유 버튼 → «홈 화면에 추가»** |
| **PC** | 안내하지 않습니다 (필요 없으니까요) |

- **이미 앱으로 열었으면** 안내가 뜨지 않습니다
- **한 번 닫거나 설치하면** 이후 재방문에도 다시 뜨지 않습니다 (이 브라우저에 기억)
- 다시 보고 싶으면 브라우저 저장소에서 `kkumttang.install.dismissed` 를 지우면 됩니다

관련 파일 — `manifest.json`(앱 이름·아이콘), `sw.js`(서비스 워커), `assets/js/pwa.js`(안내 배너),
`assets/icons/`(아이콘). 아이콘은 부서 로고를 그대로 썼습니다.

> **서비스 워커가 오래된 화면을 보여주지 않나요?** 안 그러도록 만들었습니다.
> 항상 **인터넷을 먼저** 보고, 끊겼을 때만 저장해 둔 것을 씁니다.
> 그래서 깃허브에 새로 올린 내용이 곧바로 반영됩니다.

## 7. 자주 묻는 것

**Q. 가입이 "Email address is invalid" 로 실패해요.**
Supabase 프로젝트에서 이메일 확인(Confirm email)이 켜져 있거나,
`config.js` 의 `ID_EMAIL_DOMAIN` 을 바꿨을 수 있습니다. 2-3 단계를 확인하세요.

**Q. 비밀번호를 잊었어요.**
Supabase **Authentication → Users** 에서 해당 사용자의 비밀번호를 관리자가 재설정할 수 있습니다.
(가짜 이메일이라 메일로 재설정 링크를 보낼 수는 없습니다.)

**Q. 데모 모드 데이터를 초기화하고 싶어요.**
상단 노란 배너의 **처음 데이터로 되돌리기** 버튼을 누르세요.

**Q. 새 학년이 되면 학년이 자동으로 올라가나요?**
네. 아무 것도 하지 않으셔도 됩니다.

학년을 따로 저장하지 않고, **생년월일 + 오늘이 몇 학년도인지**로 그때그때 계산합니다.
(3월 1일이 지나면 그 해가, 1·2월이면 전년도가 «학년도» 입니다. 교회 사정에 따라
`assets/js/config.js` 의 `SCHOOL_YEAR_START_MONTH` 를 1 로 바꿀 수 있습니다.)

- 2013년생은 2026학년도에 중1, 2027학년도가 되면 저절로 중2가 됩니다
- **고3이던 아이들은 3월 1일에 «졸업»(청년부) 이 되어** 주소록 기본 목록과 셀편성에서 빠집니다.
  교적 자료와 지난 셀편성 기록은 그대로 남습니다 — 주소록 상태 필터에서
  «졸업(청년부)» 을 고르면 언제든 다시 볼 수 있습니다
- **올해 중1** 화면과 개요의 «올해 중1» 카드도 해마다 저절로 새 얼굴로 바뀝니다

**생년월일을 아직 모른다면** — 편집 창의 **«태어난 해»** 칸에 `2013` 처럼 연도만 적어 두세요.
그것만으로 학년이 계산되고 해마다 저절로 올라갑니다. (생일명단에는 월·일을 모르니 나오지 않습니다.
나중에 생년월일을 채우면 «태어난 해» 칸은 저절로 비워지고 생일명단에도 나타납니다.)

**계산과 다른 아이가 있다면** (유급·월반 등) 주소록에서 그 아이를 편집해 학년을 직접 골라 두세요.
표에 «고정» 배지가 붙고, 그 아이만 계산 대신 적어 둔 학년을 씁니다.
학년 칸을 «자동» 으로 되돌리면 다시 계산값을 씁니다.

**1·2월에 헷갈리지 않도록** 주소록 제목 옆에 «2026학년도 기준» 배지가 늘 떠 있고,
아이 신상 카드를 열면 «2026학년도 기준 중3 · 자동» 처럼 풀어서 보여 줍니다.
표가 좁은 곳에서는 학년만 적고, 칸에 마우스를 올리면 학년도가 나옵니다.

> «하늘아이» 는 초등부 부서 이름입니다. 아이를 편집할 때 **하늘아이** 를 체크해 두면
> 어디서나 배지로 구분해 보여 줍니다 (학년과는 상관없이 계속 남습니다).

**Q. «재적», «재학», «전출» 이 헷갈려요.**
주소록 오른쪽 위 상태 칸을 말로 풀어 두었습니다.

| 고르면 | 보이는 아이 |
|---|---|
| **지금 우리 부서 아이들** (기본) | 잘 나오는 아이 + 오래 못 본 아이 |
| └ 잘 나오는 아이만 | «재적» 상태인 아이 |
| └ 오래 못 본 아이만 | «장기결석» 으로 표시해 둔 아이 |
| **졸업 — 청년부로 올라감** | 고3을 지나 자동으로 빠진 아이 |
| **전출 — 다른 교회로 옮김** | 직접 «전출» 로 바꿔 둔 아이 |
| **전부 (떠난 아이까지)** | 위 전부 |

한 줄로 하면 — **«재적»은 잘 나오는 아이, «장기결석»은 오래 못 본 아이,
둘을 합친 게 «지금 우리 부서 아이들»** 입니다. 졸업·전출은 부서를 떠난 아이라 기본 목록에서 빠집니다.

**Q. 장기결석 중인 아이는 어디서 관리하나요?**
주소록에서 아이 이름을 누르고 **편집 → «교적 관리» → 상태** 를 «장기결석» 으로 바꾸면 됩니다.

- 이름 옆에 «장기결석» 배지가 붙고, 개요의 «재적 인원» 에서 빠져 따로 세어집니다
- **셀편성에는 그대로 남습니다** — 담당 선생님이 계속 챙기셔야 하니까요
- 주소록 오른쪽 위 상태 칸에서 «장기결석» 만 골라 볼 수 있습니다
- 아예 다른 교회로 옮겼다면 «전출» 로 두세요. 목록에서 빠지고 기록만 남습니다

**Q. 교사·간사 명부의 "구분"이 실제와 달라요.**
원본 엑셀에 구분 항목이 없어 셀편성 호칭으로 채웠습니다
(맨 위 두 분 → 교역자·사모, 셀 담당 5명 → 교사, 나머지 → 간사).
교사·간사 화면에서 편집으로 고칠 수 있습니다.

**Q. 셀편성을 편집하다 잘못 눌렀어요.**
편집 모드 상단의 **↶ 되돌리기 / ↷ 다시하기** 로 최대 30단계까지 오갈 수 있습니다.
단축키는 `Ctrl+Z` / `Ctrl+Shift+Z` (맥은 `⌘Z` / `⌘⇧Z`) 입니다.
저장을 누르기 전에는 어떤 것도 서버에 반영되지 않으니 마음껏 만져보셔도 됩니다.

**Q. 실제 데이터를 다시 넣거나 백업하려면?**
개요 화면의 **📥 교적부 엑셀 전체 내려받기** 로 언제든 5개 시트짜리 백업을 받을 수 있고,
그 파일을 **가져오기** 로 다시 올리면 그대로 복원됩니다.
백업 파일은 개인정보가 들어 있으니 저장소에 올리지 마세요.

## 8. 개인정보 유의

이 교적부에는 미성년자의 이름·생년월일·주소·전화번호와 보호자 연락처가 들어 있습니다.

**저장소(깃허브)에는 실제 정보가 없습니다.** 코드와 가명 예시 데이터만 들어갑니다.
실제 데이터는 Supabase 안에만 있고, 접근 권한은 서버의 RLS 정책이 결정합니다.

**다만 배포된 사이트는 누구나 볼 수 있습니다.** 현재 설정은 «비로그인 전체 공개» 라서,
주소를 아는 사람은 로그인 없이 전체를 열람할 수 있습니다.

| 걱정 | 현재 상태 |
|---|---|
| 구글 검색에 뜨나요? | `robots.txt` 와 `noindex` 로 막아두었습니다. 다만 이건 «크롤링하지 말아 달라»는 요청이라 100% 보장은 아닙니다. |
| 링크를 아는 사람은? | 이름·학년·학교·생일·셀까지만 봅니다. **휴대폰·집주소·보호자 연락처·특이사항은 못 봅니다.** |
| 깃허브 저장소에서 새어나가나요? | 실제 데이터가 없으므로 새어나가지 않습니다. |
| 아무나 교사 계정을 만들 수 있나요? | 신청은 누구나 할 수 있지만 **관리자가 승인해야만** 열립니다. 승인 전에는 서버가 한 줄도 내주지 않습니다. 교사 **전화번호는 «전부 공개» 설정에서도 비공개**라 명단을 긁어서 사칭할 수도 없습니다. |
| 로그인 없이 등록·수정이 되나요? | 안 됩니다. 화면에서 버튼을 숨기는 게 아니라 **서버(RLS)에서 막습니다.** 브라우저 콘솔로 API를 직접 불러도 거부됩니다. |

### 점검 기록

실제 Postgres 에 스키마를 올려 다음을 확인했습니다.

- 비로그인으로 학생·교사·셀 테이블에 **INSERT / UPDATE / DELETE 전부 거부**
- 비로그인으로 `profiles`, `app_settings` 읽기 거부
- 비로그인·계정 없는 토큰으로 `admin_contacts()` 호출 → 0줄 (문의처는 신청자에게만)
- **승인 전 계정**으로 학생·교사·셀편성 조회 → 0줄, 등록·수정·삭제 전부 거부 (Postgres 에서 직접 확인)
- 숨긴 컬럼을 `WHERE` · `ORDER BY` · `select *` 에 넣어 우회 시도 → 전부 거부
- 교사 전화번호를 알아내 «나예요!»를 통과하는 사칭 시나리오 → 번호 비공개 + **관리자 승인**으로 차단
- 비관리자가 버전 삭제 / 가입 설정 변경 / 관리자 권한 부여 시도 → 전부 거부
- 브라우저 콘솔에서 데이터 계층 함수를 직접 호출 → 전부 거부
